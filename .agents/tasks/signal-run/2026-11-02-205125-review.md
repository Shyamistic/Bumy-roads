# Five-stop Signal Run portfolio with voice-ready publishing

The change replaces the starter’s WebGL/CMS delivery path with a semantic five-stop portfolio trail, keeping source status, public-safe claims, and the proposed Bangalore experiment in one configuration. The current production output is intentionally small: Vite emits one CSS bundle, one JavaScript bundle, and empty media markers, while the initial Voice Notes render no audio. Recorded lint, build, and browser evidence covers native navigation, responsive presentation, no-JavaScript content, and the no-canvas/no-microphone boundary. The release contract for adding a real Voice Note has two **confirmed** defects that prevent the promised ready-media path from working safely.

Watch for: **confirmed** media instructions point manifest fields at `public-signal/media/...`, which Vite does not serve from that URL; **confirmed** the player becomes ready with only consent plus an audio source, allowing the documented captions and verified transcript to be omitted.

**Verdict**: NEEDS_CHANGES

## High-level view

The active route is a deliberately small DOM experience. `src/main.jsx` enters the Signal Run shell, and Vite copies only `public-signal/`, keeping the downloaded starter’s protected visual assets outside the production output. The resulting `dist/` contains only the application bundles and empty media markers.

The portfolio’s facts, source labels, public destinations, proposal wording, budget, and contact policy live in the trail configuration. That structure keeps the diagnostic/evaluation boundary for Nexus, the sandbox-only framing for A.S.T.R.A., Vayu’s documented stale-output failure, confidential-safe work summaries, and the not-run growth test consistent across the route.

Voice Notes begin as an honest empty state rather than simulated personal media. **Confirmed** release-path gaps remain: the handoff confuses Vite’s filesystem public directory with its browser URL, and the component does not make captions and a verified transcript prerequisites for publishing a cleared recording.

## Public media paths do not map to Vite output

**Confirmed:** `vite.config.js` sets `publicDir: 'public-signal'`. Vite copies the *contents* of that directory to the production root, which the existing build demonstrates with `dist/media/.gitkeep`; it does not produce `dist/public-signal/media/`. The replacement text in `src/signal-run/content/media-manifest.js` tells Shyam to replace the null source fields with `public-signal/media/<stop>.mp3` and `.vtt`, so a real player would request a nonexistent `/public-signal/media/...` route instead of the emitted `/media/...` file.

The documented ready-media exercise did not catch this because it overrode the bundle in memory with an arbitrary same-origin missing URL. Keep the media files in `public-signal/media/`, but make the manifest contract explicit:

```js
audioSrc: '/media/nexus-prime.mp3',
captionSrc: '/media/nexus-prime.vtt',
```

The written replacement instructions need the same distinction between the local source directory and the browser-facing URL. A normal production build with one consent-cleared fixture should then exercise the exact documented contract before release.

## Voice Notes need an atomic publication gate

**Confirmed:** the source-verification handoff says the player remains empty until every related manifest field is real, and the documentation instructs Shyam to create captions and a verified transcript. The component only tests consent and `audioSrc`:

```js
const isReady = note.consentState === 'cleared' && Boolean(note.audioSrc)
```

That allows a later editor to mark a recording cleared and publish it without either `captionSrc` or `transcript`. The future-ready branch bypasses the stated caption and transcript release requirements. Gate the player on non-empty `audioSrc`, `captionSrc`, and `transcript` as well as cleared consent, and describe missing artifacts in the non-ready state so a partial record cannot look publishable.
